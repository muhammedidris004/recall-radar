## Project name
Recall Radar

## Tagline (short)
Check used baby gear against official recalls, and see exactly why. An MCP server for Alexa+, with a screen built for Echo Show.

## Description

### The problem
Recalled baby gear keeps getting resold and handed down: high chairs, cribs, strollers, car seats. The government publishes the data, but it is hard to use. In the CPSC feed, the structured `Model` field is empty in every recall since 2021, and about half of the notices never name a model number at all. So "search the product name" fails exactly when it matters, and a parent standing in a secondhand store has no easy answer.

### What it does
Recall Radar works like a careful friend. A parent says, "I'm buying a used Peg Perego Tatamia high chair, can you check it for recalls?" It finds the matching recall, then asks for the one detail that decides the answer, usually the model number and date printed on the label, and shows the recalled product's own label photo so the parent knows where to look. Details can be typed, spoken, or read from a photo of the label (local OCR).

Then it decides, and shows its reasoning. A comparison table lines up what the recall requires against what the parent said, with a clear mark for each requirement. The same chair made in February 2023 is **recalled** (model matches, date is inside "on or after June 23, 2022"); made in November 2021 it is **not covered**, and the red "Made" row shows why. It then walks the parent through the official fix and remembers the case ("Where were we with the high chair?").

### How it works
- **A real MCP server** (TypeScript, Streamable HTTP, protocol 2025-11-25, also negotiates the 2025-03-26 that the Alexa+ client sends). Five outcome-oriented tools: `check_item`, `check_label`, `get_recall`, `update_case`, `get_case`. Each returns a speakable headline and a next question, so an agentic voice host can keep the conversation moving.
- **An MCP App** (`ui://` resource) designed for an Echo Show read at arm's length: a big status hero, the comparison table, the official fix, and a progress timeline for the remedy. It fits a 1280×800 screen without scrolling.
- **Two real data sources**, 1,205 recalls: U.S. CPSC (consumer products, 2012 to Oct 2026) and U.S. NHTSA (child car seats, which have exact manufacture dates).
- **Code decides; language models never do.** The verdict compares explicit values (normalised model strings, parsed date windows, batch, serial, date codes), and every verdict carries an evidence list.
- A **simulated Alexa+ host** (a real MCP client and MCP Apps host) is included, because the Alexa+ add-on tooling is partner-only.

### What makes it trustworthy
- **Honest tiers, not guesses:** confirmed, needs one more detail, compare by appearance, not covered, or no match. It never says "safe".
- **A list that points elsewhere never clears a product.** 59 baby-product notices say things like "visit the firm's website for the complete list". For those, an unlisted model becomes "check the full list", not "not recalled". With this guard switched off, 29 of 36 such recalls were wrongly ruled out; with it on, none.
- **Tested against its own mistakes:** 54 tests, plus a benchmark generated from the real recalls with deliberately wrong inputs (typos, decoy models, wrong dates). **0 wrongly confirmed recalls across 1,924 guard cases.** We state the limit plainly: the benchmark is generated by the same extractor it tests, so it proves the decision logic, not extraction recall on unseen notices. For that we audited by hand and every finding became a test.
- A full check takes **3 to 15 ms** locally, against Alexa+'s 500 ms budget.

### Challenges
The data was the hard part. Model numbers, date codes and batches live in free text, written many different ways ("model numbers included in this recall are…", "manufactured between May 15 and August 20, 2012", "date codes 0415 or 0515"). We built the extractor from real wording, audited it against notices where identifiers were visibly present but missed, and found five classes of misses, plus real bugs that hand-testing caught and the benchmark could not (an unrelated toy recall outranking a high chair; an old car-seat recall confirmed because its name was a prefix of the user's; the label parser reading "SnugRide" as serial "ugRide"). NHTSA's own file even contains an inverted manufacture window, which the app now refuses to trust.

### What we are proud of
It is useful and honest at the same time: the screen shows the reason for every answer, and the test that matters most (never wrongly clear or confirm) is measured, not asserted.

### What we learned
For voice assistants, the answer is only half of the job. The assistant has to ask for the next useful detail and be able to explain itself on a screen.

### What's next
Push-style alerts if the platform allows them (Alexa+ add-ons answer when asked, so we cannot warn proactively today); more categories and countries (Health Canada, EU Safety Gate); an LLM extractor behind the existing `ConditionExtractor` seam, for the long tail of notice wording; and user testing with parents.

## Product feedback (one entry per tool / API / SDK used)

**Alexa+ MCP Toolkit documentation (developer.amazon.com/docs/alexaplus).** *Used for:* designing for Alexa+'s client (500 ms budget, the `initialize` handshake, `structuredContent` and `_meta.ui`, MCP Apps, the design guide, certification policy). *Worked well:* the lifecycle and policy pages are specific and useful; the 500 ms and auth requirements are clear. *Needs work:* the quickstart omits that the tooling is partner-only (the FAQ says so, the quickstart does not), and omits the CLI install command; the client is documented as sending protocol `2025-03-26` while the hackathon requires `2025-11-25`; the web simulator page never says whether MCP Apps render; `llms.txt` returns 404. *Onboarding:* confusing until we found the FAQ. *Would we build with it again:* yes, with access.

**MCP TypeScript SDK (`@modelcontextprotocol/sdk` 1.32).** *Used for:* the server, tool and resource registration, Streamable HTTP transport (stateless, JSON responses). *Worked well:* `registerTool` with Zod schemas, and `StreamableHTTPServerTransport` with `enableJsonResponse` made a spec-compliant server short; it negotiated both protocol versions correctly. *Needs work:* few examples for the MCP Apps `_meta.ui` flow. *Would build again:* yes.

**MCP Apps (UI over `ui://` resources).** *Used for:* the Echo Show result screen and the host bridge in the simulator (`ui/initialize`, `tool-input`, `tool-result`, `open-link`, `tools/call`). *Worked well:* the sandboxed-iframe model keeps the view isolated while still letting it call tools back. *Needs work:* more guidance on display sizes and fixed-height screens. *Would build again:* yes.

**U.S. CPSC Recalls API.** *Used for:* 1,028 baby and children's recalls. *Worked well:* free, no key, fresh (days old). *Needs work:* the `Model` field is empty in every recall; identifiers exist only in free text; the recall web pages return 403 to scripts. *Suggestion:* structured model, date-code and batch fields.

**NHTSA recall flat file.** *Used for:* child car seat recalls with exact manufacture windows. *Worked well:* structured make, model and manufacture dates. *Needs work:* some rows have an inverted window (e.g. campaign 26C006000); the file is 300 MB, which is heavy for a small lookup.

**Tesseract OCR (local).** *Used for:* reading label photos. *Worked well:* free and private, labels are structured text. *Needs work:* quality depends on the photo.

**Hackathon site and Devpost.** *Needs work:* the Resources page says AWS credit codes ran out on Oct 7 while the FAQ still offers a $150 credit; the deadline is shown only in GMT+5:30.

**Feature requests.** (critical) Open the Alexa+ add-on web simulator to hackathon entrants. (important) Let an add-on notify the user proactively, so a recall alert does not depend on the user asking. (important) Document MCP Apps display modes and screen sizes. (nice-to-have) Publish `llms.txt`.

**Friction log.** Ten entries with task, expected vs actual, severity, workaround and suggestion: https://github.com/muhammedidris004/recall-radar/blob/main/docs/FRICTION_LOG.md

## Open Source mini challenge (entered)

- **GitHub username:** muhammedidris004
- **What I did, how it works, why it matters:** `mcp-apps-sim` is a new, separate MIT-licensed project built during the hackathon window: a browser-based MCP Apps host and test client for any MCP server. Alexa+'s add-on tooling and web simulator are partner-only, so there was no way to test a voice-and-screen MCP server end to end. You point the tool at any Streamable HTTP MCP server (`npx github:muhammedidris004/mcp-apps-sim <url>`) and get: pre-flight checks drawn from the public Alexa+ MCP docs (handshake across protocol versions, capabilities, tool description and schema quality, `ui://` resources and MIME type, round-trip latency against a 500 ms budget); tool forms generated from JSON Schema; a sandboxed MCP Apps host that renders `_meta.ui.resourceUri` apps on Echo Show-sized screens and bridges `ui/*` and `tools/call` over `postMessage`; and a protocol log with browser and server timings. A small CLI proxy lets it work with servers that send no CORS headers, and never exposes `--header` secrets to the page. It has no dependencies and 16 tests against a fake MCP server, including deliberately bad servers. It matters because the same gap blocks every hackathon entrant (and every developer building an MCP App) who cannot reach a real host: it makes the MCP Apps path testable and catches problems such as a wrong MIME type, a vague tool description, or an over-budget response before they reach a user. It is the generic half of the simulator used by the primary submission, Recall Radar.
